🧠 Kev · 数据流转动画图解

这是 学习文档 的 00 号配套页：纯离线、无外部依赖，用粒子沿管道流动演示 Kev 的四条主线——推理请求、block-causal 掩码、指针打分、训练/校准闭环。 右上角可暂停动画或切换深浅主题。

① 一次推理请求：state + questions → probabilities

粒子从左侧进入，依次穿过契约层、编码、prefill、指针头、答案回写，最后从右侧返回。

记住第一性改造：只 prefill、不 decode。粒子穿过 backbone 时不会变成文字，而是在 <decide> 位置留下一个隐向量，供 PointerHead 给候选项打分。

② block-causal 掩码：共享 state，隔离分支

左侧是打包序列（state 段 + 两个问题分支）；右侧是注意力矩阵——亮格表示"可 attend"。 每个分支能读 state（第一行整条亮），但读不到兄弟分支。

branch_mask_batch() 把这张矩阵变成 [B,1,L,L] 的加性掩码（不可 attend 处填 -inf）。hybrid 骨干（DeltaNet）实现不了这张任意掩码 → 改走 row form： state+单分支拆成一行独立因果序列，数学上等价。

③ PointerHead：不做词表 softmax，而是给候选项打分

<decide> 隐向量当 query，每个 </opt> 边界隐向量当 key，点积 → 每个选项一个 logit。 粒子从两侧汇聚到点积节点，代表信息在此汇合。

noul → p(true) choice → argmax + confidence score → Σ i·p[i] 期望等级

④ 训练闭环 与 评估校准回路

左：一条 record 绕圈被训练（encode → prefill → loss → backward → step）。 右：训好的 checkpoint 走"评分 → 指标 → 拟合温度 → 发布"的校准回路。

校准纪律（04 文档）：温度只能拟合在训练语料之外的 development 行； round 21 起，受温度影响的判据没有注册 temperature 池会被 kev.rounds validate 直接拒绝。
