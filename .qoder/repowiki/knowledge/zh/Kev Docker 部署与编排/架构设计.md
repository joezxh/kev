模块以 deploy/ 为根，按模型维度复制一组 compose/Dockerfile：Dockerfile.4B 与 Dockerfile.0.8B 从本地源码构建 kev-server（FastAPI 推理服务，端口 8008），Dockerfile.playground 单独构建 Next.js 演示 UI（端口 3000）；两个模型共用同一 playground 镜像。

- 编排层：docker-compose-4B.yml / docker-compose-0.8B.yml 定义 kev-server + playground 两个服务，共享网络 kev-net，playground 通过 Next.js rewrite 把 /kev/* 代理到 http://kev-server:8008，无需暴露 8008 端口。
- 入口层：deploy-windows.ps1（PowerShell）与 deploy-linux.sh（Bash）是统一入口，通过 -Model/--model 在 4B 与 0.8B 之间切换，自动选择对应的 compose、默认 checkpoint 目录与 Hub id。
- 数据层：deploy/runs/<name> 挂载为 /kev/runs/<name>，存放 LoRA 适配器快照（head.pt + adapter_config.json + adapter_model.safetensors）或完整权重；HF 基座缓存走 kev-hf-cache 卷，支持离线运行。
- 安全边界：KEV_API_KEY 透传启用 Bearer 认证；Playground 前端 lib/kev.ts 内置兜底 key，需与服务端一致。
- 依赖方向：脚本 -> docker compose -> 镜像 -> 容器内 kev.serve；.dockerignore 排除 .git、node_modules、runs/、*.md 等无关文件以缩小构建上下文。
