模块由两个并列的 Skill 子目录组成，每个 Skill 遵循统一的三件套结构：`SKILL.md`（面向 Agent 的 YAML front-matter + 分阶段操作手册）、`README[_CN].md`（用户文档）、`scripts/`（可编辑的 Python 工具）。

- `kev-deploy/`：单文件 Modal App `scripts/kev_serve.py`，通过 `modal deploy` 构建镜像、加载 Hugging Face checkpoint、在 GPU 上暴露 TypeSafe `/v1/systemone` 与 `/v1/models` 接口，支持按 `KEV_MODEL`/`KEV_GPU`/`KEV_REGION`/`KEV_MIN_CONTAINERS` 等环境变量选择模型、GPU、区域与常驻容器数，并默认空闲 5 分钟后缩容至零。
- `kev-finetune/`：多脚本流水线，依赖关系为 `extract_workload.py → convert_data.py → generate_data.py → split_data.py → kev_modal.py`；`references/` 存放 data-format / data-generation / deploy / hill-climbing 四组参考文档（中英双语），`assets/workload.example.json` 作为 workload spec 模板。
- 两个 Skill 共享同一协议边界：TypeSafe System One 的 `POST /v1/systemone`（state + questions）与 `GET /v1/models`，并通过 `Authorization: Bearer <key>` 鉴权；部署产物均输出 bf16 权重，可在 `kev-deploy` 中直接复用 `kev-finetune` 产出的 checkpoint。
- 依赖方向单向向外：Skill 仅依赖 `modal`、`kev`（以固定 commit 克隆）、Hugging Face Hub 与任意 OpenAI-compatible 生成端点，不反向引用仓库其他代码。
