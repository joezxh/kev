仓库根通过 `pyproject.toml` 暴露 `kev` 包（`setuptools` 打包 `kev`, `kev.console`, `kev.console.stages`），所有子模块都作为该包的依赖或附属资源被消费：
- 运行时核心在 `kev_library`（model/train/benchmark/suite/checkpoint/serve/publish/rounds/experiment 等），对外提供 TypeSafe `/v1/systemone` 契约；
- 研究编排层 `modal_app.py` 是 Modal 云入口，复用 `kev.experiment.execute_trial`、`kev.benchmark.evaluate_records`、`kev.mirror`、`kev.rounds` 等同一套代码路径，仅把设备从 CPU/MPS 切换到 GPU，并通过三个共享 Volume（`kev-hf-cache` HF_HOME、`kev-runs` 试验输出、`kev-leases` 全量尝试租约）实现本地与云端状态同步；
- 评测数据集中在 `evals_and_scripts`（冻结的 decision/transfer/documents/longdoc/hard/night2 等套件及其 manifest），由 `kev.suite.load_split` 从 Hub mirror 拉取并 sha256 校验，训练与 benchmark 共用同一份分区；
- 训练超参与审计协议归档在 `experiments`（JSON 计划、校准协议、release 元数据），被 `kev.experiment` 和 `kev.rounds` 读取；
- 部署侧 `deploy`（Docker Compose + Next.js Playground）与 `deploy_scripts`（WSL2 一键初始化）消费已发布的 Kev checkpoint，Playground 前端则反向代理到 `kev.serve`；
- `docs_and_skills` 把 model-cards、README、SKILL.md 等面向用户与 Agent Skill 的资源集中发布。
启动时，`AGENTS.md` 与 `README.md` 共同描述命令约定（`uv sync` → `uv run python -m kev.*` / `modal run modal_app.py::*` / `playground npm run dev`），CI（`.github/workflows/ci.yml`）只跑单元测试与 playground lint/typegen，不触发训练。
