## 1. 使用的工具与方案

仓库采用多语言、多层次的依赖管理策略：

- **Python 包**：使用 `uv`（现代 Python 包管理器）作为解析器，配合标准 `pyproject.toml` 声明依赖，并生成 `uv.lock` 锁定文件。构建后端为 `setuptools.build_meta`。
- **Node.js 前端**：Playground 子项目使用 `npm`（`package.json` + `playground/package-lock.json`），基于 Next.js 16.3.5。
- **Agent Skills**：通过 `skills-lock.json` 锁定从 GitHub 拉取的 Cursor/Skills 插件（如 `deslop`、`grill-me`、`unslop`），每个 skill 附带 `computedHash` 用于校验。
- **Docker 构建**：预构建基础镜像 `deploy/Dockerfile.python-torch` 内嵌 PyTorch wheel，加速离线构建。

## 2. 关键文件

- `pyproject.toml` — 主包 `kev` 的元数据、运行时依赖、可选依赖（`serve`、`mlx`）、开发依赖组（`dependency-groups.dev`）。
- `uv.lock` — uv 生成的完整依赖树锁定文件，包含每个包的 sdist/wheel URL 与 sha256 hash。
- `playground/package.json` + `playground/package-lock.json` — Node.js 依赖声明与锁定。
- `skills-lock.json` — Agent skills 来源与哈希锁定。
- `.python-version` — 指定项目所需 Python 版本（由 uv/poetry 等工具读取）。
- `deploy/Dockerfile.python-torch` — 预装 torch 的基础镜像，设置国内 PyPI 镜像。
- `deploy/docker-compose.yml` / `docker-compose-0.8B.yml` — 通过环境变量 `PIP_INDEX_URL` 注入 PyPI 镜像地址。

## 3. 架构与约定

### Python 依赖声明

`pyproject.toml` 中按用途分层：

- **运行时依赖**（`project.dependencies`）：`accelerate`、`datasets`、`torch>=2.6,<2.9`、`transformers>=5.17,<6`、`peft`、`pydantic`、`scikit-learn`、`jinja2`、`simpleeval` 等。
- **可选依赖**（`project.optional-dependencies`）：
  - `serve`：FastAPI、`typesafe-sdk`、Uvicorn、SQLAlchemy、psycopg[binary]、requests、`mlx-lm`（仅 macOS arm64）。
  - `mlx`：仅 `mlx-lm>=0.31.3,<0.32; sys_platform == 'darwin' and platform_machine == 'arm64'`。
- **开发依赖**（`dependency-groups.dev`）：httpx、matplotlib、`modal==1.5.5`（精确锁定）、pytest。
- **Python 版本约束**：`requires-python = ">=3.12,<3.14"`。

### 平台条件依赖

`mlx-lm` 仅在 Apple Silicon (`sys_platform == 'darwin' and platform_machine == 'arm64'`) 上安装，其他平台视为 no-op。这是通过 PEP 508 环境标记实现的。

### 锁定与可复现性

- `uv.lock` 记录每个依赖的精确版本、source registry、sdist/wheel URL 及 sha256 hash，确保跨机器一致。
- lock 文件顶部声明 `requires-python = ">=3.12, <3.14"` 和 `resolution-markers`（win32/emscripten 分支）。
- Node.js 侧使用 `package-lock.json` 锁定 npm 依赖树。

### 国内镜像配置

为避免 Docker Hub 与 PyPI 在中国大陆不可达的问题：

- `deploy/Dockerfile.python-torch` 设置：
  ```
  ENV PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple \
      PIP_EXTRA_INDEX_URL=https://mirrors.aliyun.com/pypi/simple/ \
      UV_DEFAULT_INDEX=https://pypi.tuna.tsinghua.edu.cn/simple \
      UV_LINK_MODE=copy
  ```
- docker-compose 通过 `${PIP_INDEX_URL:-}` 将宿主环境变量透传给容器。
- 基础镜像使用 `docker.m.daocloud.io/library/python:3.13-slim-bookworm`（DaoCloud 镜像）。

### Agent Skills 依赖

`skills-lock.json` 以结构化方式记录每个 skill 的来源（GitHub 仓库 + 路径）与 `computedHash`，用于校验技能包完整性。例如：

```json
{
  "version": 1,
  "skills": {
    "deslop": {
      "source": "cursor/plugins",
      "sourceType": "github",
      "skillPath": "cursor-team-kit/skills/deslop/SKILL.md",
      "computedHash": "8883a7d..."
    }
  }
}
```

## 4. 观察到的约定与约束

- **PyTorch 版本范围固定**：`torch>=2.6,<2.9`，在 `pyproject.toml` 与 `Dockerfile.python-torch` 中保持一致，避免 CUDA wheel 不匹配。
- **Transformers 版本范围固定**：`transformers>=5.17,<6`，与 PyTorch 版本区间协同。
- **Modal 开发依赖精确锁定**：`modal==1.5.5`（而非范围），确保 CI 行为稳定。
- **可选依赖按场景拆分**：`serve` 与 `mlx` 分离，减少非必需平台的安装包体积。
- **构建系统明确声明**：`build-system.requires = ["setuptools>=77"]`，`build-backend = "setuptools.build_meta"`。
- **无私有 PyPI 源**：所有依赖来自官方 PyPI（`https://pypi.org/simple`），仅通过环境变量切换国内镜像；未发现 `pip.conf`、`PYPI_MIRROR` 或 `GOPRIVATE` 类配置。
- **无 vendoring**：未使用 `vendor/` 目录或 `--no-index --find-links` 形式的本地缓存策略；依赖均在线解析。
- **Node.js 依赖使用 npm 锁定**：`playground/package-lock.json` 存在，但未见 pnpm/yarn 锁定文件。
- **Skills 通过哈希校验**：`skills-lock.json` 中的 `computedHash` 字段用于验证第三方 skill 内容未被篡改。
