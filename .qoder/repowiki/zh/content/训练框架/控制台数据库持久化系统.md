## 引言
本文件聚焦于 Kev 控制台的数据库持久化子系统，围绕作业编排、产物与血缘、事件流、场景配置、API Key 与用量统计、蒸馏 Provider 用量等能力进行系统化说明。该子系统以 SQLAlchemy Core 为核心，通过环境变量在 SQLite 与 PostgreSQL 之间切换；日志文件作为真相源，events 表提供可分页的 UI 尾部与 SSE 续传；状态机集中校验，避免非法转移。

## 项目结构
控制台持久化相关代码主要分布在以下位置：
- 数据访问层：`kev/console/db.py`（Store、DDL、迁移、事务代理、作业/产物/事件/API Key/用量/Provider/场景等）
- HTTP 路由层：`kev/console/app.py`（FastAPI 路由、SSE、产物读取、闸门、密钥管理、用量查询、内部端点、进程装配）

- 初始数据生成脚本：`scripts/gen_console_schema.py`（种子 SQL 生成）
- 后端切换测试：`tests/test_console_backend_switch.py`（SQLite/PostgreSQL 环境验证）

### 作业状态机与事务
Store.transition 将状态校验与写入合并为一条语句，结合 BEGIN IMMEDIATE 拿写锁，避免并发下「已取消的作业最终被标记成功」的问题。SOURCES 由 ALLOWED 反推，确保「能到达目标状态的来源集合」正确且稳定。

```mermaid
flowchart TD
Start(["进入 transition"]) --> CheckSources["计算允许的来源集合 SOURCES[to]"]
CheckSources --> HasSources{"是否有来源?"}
HasSources --> |否| SkipUpdate["跳过 UPDATE，直接回查当前状态"]
HasSources --> |是| ExecUpdate["BEGIN IMMEDIATE + UPDATE WHERE status IN (sources)"]
ExecUpdate --> Changed{"是否变更?"}
Changed --> |是| EndOK["返回成功"]
Changed --> |否| Recheck["SELECT 当前状态"]
Recheck --> Exists{"作业存在?"}
Exists --> |否| RaiseKey["抛出 KeyError(job_id)"]
Exists --> |是| RaiseValue["抛出 ValueError(非法转移)"]
SkipUpdate --> Exists
```

## 性能与一致性
- 连接与事务：每线程一个连接，WAL 模式提升读并发；_Conn 代理补齐自动提交语义，处理 idle-in-transaction 与 InternalError 后重连
- 状态机：transition 使用 BEGIN IMMEDIATE 与 SOURCES 集合，保证校验与写入原子性
- 事件追加：逐行 INSERT RETURNING id，避免 executemany 不支持 RETURNING 的问题；空批次返回 0，防止游标误判
- 用量统计：按 key_id 与时间范围聚合，p99 延迟计算
- 后端切换：SQLite 默认，PostgreSQL 通过环境变量配置；测试覆盖 URL 构建与往返

## 故障排查指南
- 状态非法转移：transition 抛出 ValueError，检查 ALLOWED/SOURCES 与当前状态
- 作业不存在：transition 抛出 KeyError，确认 job_id 是否存在
- 事件游标异常：append_events 空批次返回 0，前端需正确处理 after_id 不变的情况
- 后端连接问题：InternalError 触发回滚与新连接重试；PostgreSQL idle-in-transaction 超时会回滚
- 产物缺失：register_finished 失败会记 system 事件并重抛，检查 artifacts.register 与日志
- 端口冲突：独立运行控制台禁止绑定 8008（推理端点），使用默认 8790 或设置 KEV_CONSOLE_ALLOW_SERVE_PORT=1

## 结论
控制台数据库持久化系统以 Store 为核心，结合 FastAPI 路由与 SQLAlchemy Core，提供了健壮的作业编排、产物血缘、事件流、场景配置与用量统计能力。通过环境变量灵活切换 SQLite/PostgreSQL，配合严格的作业状态机与事务代理，确保一致性与可靠性。SSE 事件流与 Last-Event-ID 续传机制使 UI 体验流畅，而产物与日志文件的真相源定位保障了可观测性与可审计性。
