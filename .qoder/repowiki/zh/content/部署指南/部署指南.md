## 简介
本指南面向希望将 Kev 服务化并投入生产的团队，覆盖本地部署（WSL2、Windows PowerShell、Docker）、云端（Modal）部署、容器化与编排、生产高可用与安全、监控日志、模型规模与硬件选型、HTTPS 与访问控制、以及故障排除与性能调优。文档以仓库内现有实现为依据，重点围绕以下入口：
- **Docker 本地部署**：通过 Docker 容器化部署，支持 GPU 加速和多种运行环境
- **WSL2 自动化部署**：专为 Windows 用户优化的自动化部署脚本
- **Windows PowerShell 部署**：原生 PowerShell 兼容的 Docker 部署方案
- **本地推理服务**：通过 Python 包内的 serve 模块启动 HTTP API
- **云端推理服务**：通过 Modal 应用一键部署 HTTPS 端点，支持按模型自动选择 GPU 资源
- **训练/实验流程中的 Modal 调用**：在 rounds 流程中异步调用 Modal Function

## 核心组件
- **Docker 本地部署**
  - 基于 Debian Slim + Python 3.13 的轻量级镜像
  - 支持 GPU 直通和 CPU 模式自动检测
  - 提供健康检查和自动重启策略
- **WSL2 自动化部署**
  - 一键初始化 WSL2 环境，自动检查 Docker 和 NVIDIA 驱动
  - 生成环境变量配置文件和 Docker Compose 配置
  - 支持 GPU 加速和 CPU 模式自动检测
- **Windows PowerShell 部署**
  - 完全兼容 Windows PowerShell 环境
  - 自动检测 Docker 和 GPU 环境
  - 内置服务就绪检测和 API 测试

  - 暴露 /v1/systemone、/v1/systemone/permute、/v1/systemone/separate 等接口
  - 提供 /v1/models 查询可用模型信息
  - 使用 HTTP 中间件进行请求处理

  - 基于 Debian Slim + Python 3.13 的镜像
  - 挂载 HuggingFace 缓存卷与 runs/leases 卷
  - 根据环境变量选择模型与 GPU（如 KEV_MODEL），不同模型自动匹配 L40S/B200/H200/H100
- 实验流程中的 Modal 调用
  - 在 rounds 流程中异步调用 Modal Function，处理超时与结果过期等异常

### 容器化与 Kubernetes 编排
- **Docker 镜像**
  - 基于 Debian Slim + Python 3.13，按需安装依赖
  - 将 serve 模块作为进程入口，暴露 HTTP 端口

  - 生产环境服务配置（GPU 支持、资源限制、健康检查）

- **Kubernetes 编排**

  - HorizontalPodAutoscaler：基于 CPU/GPU 利用率或自定义指标扩缩容
  - ConfigMap/Secret：注入环境变量（模型名、密钥等）

## 故障排除
- **常见问题**
  - 模型加载失败：检查 HF 缓存卷挂载与网络连通性
  - GPU 不可用：确认驱动版本与容器 GPU 支持
  - 冷启动慢：预热模型或调整 Modal 的最小实例数
  - **新增** Docker 环境问题：检查 Docker Engine 状态和 NVIDIA Container Toolkit
  - **新增** WSL2 环境问题：检查 Docker Desktop 配置和 WSL2 状态
- **Docker 特定问题**
  - **新增** 镜像构建失败：检查网络连接和依赖安装
  - **新增** GPU 无法识别：检查 NVIDIA 驱动和 Docker GPU 直通配置
  - **新增** 端口冲突：修改默认端口或使用不同的端口映射
  - **新增** 内存不足：调整 MAX_BATCH 和 KEV_PREFIX_CACHE 参数
- **WSL2 特定问题**
  - **新增** Docker 未检测到：确保 Docker Desktop 已启动且 WSL2 后端启用
  - **新增** GPU 无法识别：检查 NVIDIA 驱动版本和 Docker GPU 直通配置
  - **新增** 端口冲突：修改默认端口或使用不同的端口映射
- **Windows PowerShell 特定问题**
  - **新增** PowerShell 语法错误：确保使用正确的 PowerShell 语法
  - **新增** Docker 命令失败：检查 Docker Desktop 是否在运行
  - **新增** GPU 检测失败：确认 NVIDIA 驱动正确安装
- **调试步骤**
  - 查看服务日志与 Modal 函数日志
  - 逐步缩小问题范围（网络/依赖/模型/硬件）
  - **新增** 使用 `docker logs -f kev-server` 查看 Docker 部署日志
  - **新增** 使用 `docker compose logs -f kev-server` 查看 WSL2 部署日志
  - **新增** 使用 `docker stats kev-server` 查看资源使用情况
- **恢复策略**
  - 重启 Pod/容器，回滚到稳定版本
  - 切换备用 GPU 类型或模型
  - **新增** 重新运行 `deploy.sh clean` 清理 Docker 环境
  - **新增** 重新运行 `deploy-wsl2.sh` 重置 WSL2 部署环境

## 结论
Kev 提供了灵活的部署选项：**新增的 Docker 本地部署**为各种环境提供了开箱即用的体验，结合 WSL2 自动化部署、Windows PowerShell 支持和 Modal 云端弹性扩展。通过合理的 GPU 选型、容器化编排与生产级安全与监控配置，可在保证性能的同时控制成本。建议在灰度发布阶段结合监控与告警，逐步扩大流量，确保稳定性与用户体验。

**推荐部署流程**：
1. **首次部署**：使用 `deploy.sh` 进行 Docker 快速部署
2. **Windows 用户**：使用 `deploy-wsl2.sh` 进行 WSL2 自动化部署
3. **PowerShell 用户**：使用 `deploy-windows.ps1` 进行原生 PowerShell 部署
4. **生产环境**：结合 Kubernetes 编排和监控体系
5. **云端扩展**：使用 Modal 进行弹性部署和成本优化
